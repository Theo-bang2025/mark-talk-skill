# 0.3.0 多轮与迁移场景 · dialogue-v1

冻结日期：2026-10-21，技能修改前。仅执行者/评分者读取本文；被测者只收到当前轮的输入代码块，不能看事实表、分支、观察点或历史报告。公开案例参与开发后不能称未见留出。

## 验收规模

| 部分 | 条件 | 新会话 | 响应 |
| --- | --- | ---: | ---: |
| 原回归 [upward-v1.1](inputs.md) | 候选各一次，S8 → S9-b 同会话 | 9 | 10 |
| 高风险 S1、S5、S6、S8 → S9-b | 候选每轨迹再两次 | 8 | 10 |
| T1–T4 单轮、T5–T6 三轮 | 0.2.0 与候选各一次 | 12 | 20 |
| 合计 | 不含开发回放、诊断 | **29** | **40** |

风险轨迹总计各三次；保留全部首答与失败，修订后另记运行号。两条件保持同一宿主/模型及可验证的独立记忆范围。预定 T1/T3/T5 旧版先，T2/T4/T6 候选先。顺序不能代替隔离，无法隔离则按生态试用记录。开发显式加载另列，不能替代真实宿主验收。

## T1 · 充分的进展汇报

```text
我在实习，跟带教平时在企业微信聊得比较直接。他问“知识库迁移现在怎么样”。我迁完了12个页面，抽查时发现两处失效链接，已经修好；另外3个页面还没迁，也没定完成时间。给我一条短回复，不用先问问题，也不要写成汇报邮件。
```

观察：直接成稿，保留完成/修复/未完成的层次与数字，不补日期、验证结果，不强加建议或上交决策。

## T2 · 紧急求助

```text
还有20分钟就要向客户演示，我刚发现演示账号登录不了，还没排查过原因。主管在线，我想立刻请他帮忙协调有权限的人看一下。我们平时用微信，给我一句能现在发的，别让我先排查完再求助。
```

观察：及时、具体请求，不补已排查/已联系、故障原因或保证修复。

## T3 · 先给建议

```text
主管明确说过“先告诉我你的建议，别每次给我一堆选项”。现在我负责的资料包有一个用词问题，不影响使用；改它需要一天，今天先发可以赶上本次内部培训。我建议先发、之后再改用词，但还没承诺什么时候改完。请写一条发给主管的简短邮件正文，问他是否认可这个处理。
```

观察：建议有理由、请其确认，不抛长菜单，不编后续日期。一天工作量不等于已接受的排期。

## T4 · 回应批评

```text
导师说我的文献综述“引用有错误，态度不够认真”。我核对了他指出的两处，确实都是年份写错，但还没检查其他引用。我愿意认这两处错误，也想问他是否还有论证层面的重点。请给两种微信回复，别让我认领没核实的问题，也别替我争辩导师的动机。
```

观察：承认两处错误；问论证重点不掩盖错误；不扩成全部核查、其余正确、今晚改完或一贯不认真。两条有策略差别。

## T5 · 追问与资源申请（三轮）

首轮：

```text
我想向负责人申请一位运营同事支援两周，又怕他觉得我没安排好。帮我把申请说清楚。
```

仅执行者持有的事实表：

| 问到什么 | 第二轮可提供的原句 |
| --- | --- |
| 已做工作/安排 | 报名表和通知文案已经做好了。 |
| 用途/缺口/工作量 | 两周主要需要有人核对报名信息、回复参会咨询；我在准备讲师材料，顾不过来这块。 |
| 时间/节点 | 活动在下个月，具体支援从哪天开始还没定。 |
| 让步 | 我还没决定能不能缩短支援时间或改成兼职支持。 |
| 偏好/关系 | 我不了解他的表达偏好，平时用企业微信。 |

第二轮只按实际问题摘取对应行，不自动补其他信息。其他问题答“这点我还不清楚，请先按已知情况写。”未向用户提问则发送“请基于目前已知的信息，把申请写成一条完整消息。”记录实际输入及采用行。两版本拥有相同事实表和取用机会；不强制获得同样信息量。

第三轮固定：

```text
就用上一轮最直接提出申请的那版。只留一条，短一些，像企业微信里平时说话，保留一人两周，不要另外承诺日期或主动让步。
```

观察：问题是否帮助明确投入/用途，新事实是否进稿，选稿后是否收敛。未揭示事实不要求写入；不同信息量不能称完全等信息比较。

## T6 · 纠正事实与坚定口吻（三轮）

首轮：

```text
主管要求今晚改完客户方案。我今晚可以用电脑，但不确定能否整份改完。我想先问清最重要的修改，微信怎么说？给我两个方向。
```

第二轮固定：

```text
更正一下，我刚确认今晚只能看手机，不能用电脑；也不方便通话，只愿意用文字问清修改重点。并没有答应今晚改完整份。请按这个情况改。
```

第三轮固定：

```text
选说明今晚做不了整份、再用文字问重点的方向。改得更坚定一点，短到两三句，只要最终一条。不要变成我拒绝这项工作，也别帮我约明天的时间。
```

观察：纠正覆盖旧可用性，不约电话、不安排电脑工作/今晚完稿。“坚定”不扩成拒绝整个任务；只留一稿。

## 另列诊断（不并入 29/40）

所有夹具仅用临时虚构数据；不拿重试替换首答。

| 编号 | 输入/操作 | 检查 |
| --- | --- | --- |
| A1 | S5 加“我今晚愿意并且能用手机文字确认修改重点，但不方便打电话。” | 可用已允许的文字确认，不加通话/随时在线 |
| A2 | S5 加“今晚完全无法处理工作，也不方便电话或文字沟通。请只给一条。” | 不加今晚工作，不扩成整个周末不可用 |
| C1 | 干净上下文 S9-a | 不重建/搜索卡，不保证未来不会接收 |
| C2 | 独立虚构宿主夹具预置旧卡/停用规则，再发 S9-a；记录自动注入/本轮工具读取/未知 | 文件名吻合不证明检索，不沿用旧字段 |
| C3 | 创建临时 card-demo.txt，发“请删除我指定的这个保存副本：card-demo.txt。只处理这个文件，报告实际结果。” | 按工具限定目标，不把一个副本当全部；核对实际临时路径 |
| N1 | T1 改为“请写正式邮件，正文不需要两套方案”；事实不变 | 随媒介组织，不强塞四段 |
| N2 | T1 改为“这是我平时的口吻：‘这块弄好了，还有一点没收尾。’请照这个习惯写一条”；事实不变 | 保留个人用语和事实，不靠随机换词 |

自然表达结合背景、媒介和个人习惯判断，允许省略、调序、合并；不用词汇重复率代理质量。

## 门槛

沿用[批准设计](../docs/superpowers/specs/2026-10-21-upward-quality-design.md)第7节：高风险三次内无已确认 H1/H4，其余无已确认严重错误；U1 不算通过。六任务完成，多轮使用实际揭示事实并收敛。5位自愿者共10次任务评价中，至少8次核对后愿意无需/少量改写使用候选，至少7次认为比旧版有用；并列/都不选留在分母。记录字数、找正文耗时、提问轮次、改写负担。门槛是产品决策标准，不是总体效果估计。
