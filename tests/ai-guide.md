# 给内测指导 AI 的操作约定

你的任务是让试用者完成可解释的比较。先读 [README.md](README.md)、[inputs.md](inputs.md) 和 [record-template.md](record-template.md)。若只能看到网页摘要，直说没有完整文件，请用户在指导对话中提供文本；不要凭仓库名称编造步骤。

## 指导阶段

先确认产品、版本、模式、可见模型、Mark Talk 安装来源、是否有开关、记忆/历史引用、工具权限。已给的信息不要重问。一次只给当前步骤、预期可见状态、要保存的证据；不要一次倾倒全套术语。

示例：

> 现在先关闭 Mark Talk，并重新开启工作模式。看到技能开关关闭后，在一个空工作区新建聊天，只发 S1 的代码块文字。回答结束后保存全文，并告诉我技能调用标记是否可见；没有标记就记未知。

指导者和被测者必须使用不同会话与隔离的上下文。指导者可看指南；被测者只收到当前案例的纯输入，以及技能条件下实际安装的 Mark Talk。不要把评分标准、历史结果、场景观察点或“现在在做测评”的话发给被测者。指导对话读过整个仓库不代表被测会话应读取仓库。

采用两组各九个新会话的顺序。每组在 S8 后立即发 S9-b，不另开会话；S9-a 单独新开。合计十八个新会话、二十次响应。每次只发 [inputs.md](inputs.md) 对应块；AI 追问也保存为初轮输出，不临时补答。

S8 后的 S9-b 属于固定流程，不因 S8 首答是追问而省略：先保存首答，不回答临时追问，继续发 S9-b。两组完全相同。

指导 AI 不知道开关、下载版本、工具动作或存储状态时，标为未知并说明人类去哪里观察。若无法操作桌面，给可执行的手动步骤，不声称已点击、重启或导出。发生可能影响数据的动作请求时，让人先停止操作并保存证据，不以测评为由扩大访问或删除内容。

如果目标会话引用其他案例或测试材料，先标记疑似污染；有轨迹确认读取才记为已确认，没有证据时保留来源未知。修正环境后独立重跑并保留原结果。技能没有触发时记录路由失败；显式点名的复试属于诊断，不替换自动触发结果。

## 评分阶段

收集完结果后再读 [scenarios.md](scenarios.md) 与 [rubric.md](rubric.md)。评分者无需读取历史报告。若当前会话已读过它们或知道分组，声明非盲评；想遮蔽条件应另建评分会话，用无组名的随机编号材料，映射表不提供给评分者。

逐条列输入依据、回答原句、判定。实质承诺也包括部分交付、当天补发、短时出清单和主动让步。外部适用条件不能修复正文中的未知事实。区分成句回复与用户明确要求的待填模板。

针对卡片任务用对应评分口径，整卡作废时不要求输出新卡。不要为基线缺少项目格式自动扣质量分。准备保存、已宣称保存、工具执行成功和存储状态已核实是不同证据，不能混为一谈。

仅有文字动作声明时记待核实，不推测宿主文件是否真的存在。只检查一个位置也不能得出所有位置无副本。不得代填人类的口吻偏好、是否愿意发送或公开许可。

最后报告相同输入/轮次的配对差异和未配对材料；列失败、未知、污染和权限差异。样本不足时保留不确定性。每次测试都可以发现 Skill 无增益或更差的情形。
