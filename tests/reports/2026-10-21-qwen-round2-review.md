# 第二轮千问测评复核

日期：2026-10-21。对象：Mark Talk `0.2.0`，提交 `82dd114484f0a92068c6096c4843a68202083807`。

本次只复核和规划，未改写技能。近期方案见[向上沟通质量设计](../../docs/superpowers/specs/2026-10-21-upward-quality-design.md)，阶段安排见[路线图](../../ROADMAP.md)。

## 可以得出什么结论

本轮提供了有用的缺陷证据。技能组较少补写工作成果，关系卡纠正更完整，也能给出有差别的沟通做法。S1、S5 仍有未确认的行动或时间承诺；另有评分漏判。尚不能据此宣布稳定提升、接近零失误，或用户已经愿意直接使用。

近期值得投入的方向是：从真实材料中组织出有说服力的回复，并在必要时通过多轮补齐背景、收敛成用户自己的表达。事实边界作为验收底线，与有用性一起检查。

以下仅重算提交包的原分，**不是本项目重新认可的质量分**。

剔除已发现的污染样例，不会自动证明其他样例完全未受影响。原稿“可比 9 对”可作为暂定整理口径，不能升级成受控对照。

不将首轮旧评分均值与本轮 v2 均值画成进步曲线。两轮输入留存、评分、安装和宿主状态不同。可以追踪同类错误是否再次出现。

“自我认证”在本轮技能输出出现、基线输出未出现，是本次观察；它是否由 0.2.0 的特定改动引起、是否比没有认证更容易让用户漏查，都还没有实验依据。

## 3. 原句复核与被漏掉的问题

| 案例 | 保留的进步 | 需要纠正或继续检查 |
| --- | --- | --- |
| S1 | 尝试协商交付范围、区分争取协助与先交部分内容 | “我这边催了”“我按五点前交”“数据到了我当天补上”均无输入支持；还有“成本/收益”这一范围补写。H1 成立 |
| S2 | 澄清论证维度、请导师定位典型段落，有实际帮助 | 开头断言导师“脑子里有具体不满的段落”，输入并不能证明；四类问题清单可能增加阅读负担。“线上线下都可以”也需核实用户可行性 |
| S3 | 不再虚构自测成果；把延期/范围讨论写成待决策的问题 | “进场时间我这边可以配合对方的安排”可能改变关键排期，不能因为像礼貌用语就默认无实质负担；“说服力翻倍”无依据 |
| S4 | 完成材料、两次试讲与未上线分开说明，没有编试讲正反馈 | 三版主要在请主管定安排、审材料或接收简报；“上线安排等你定”未确认决策归属，也可能让用户显得缺少主动判断。两次试讲是行动证据，不自动成为效果验证 |
| S5 | B 版较贴近用户的拒绝目标，并追问用途时间 | A 版“手机我随时能看”“今晚我可以先……过一遍”擅加可用性和工作。H1 成立。开头猜测真实需求可能是周一，缺少本例依据 |
| S6 | 澄清方向、提醒自己先看材料，有可取的结构 | 第三版“您今天或明天什么时候方便……大概占用您十分钟”含未确认可用日期、会谈形式和时间承诺；外侧“觉得不合适就删掉”不能修复正文。按现有 rubric 应补记 H1，不能保留 12 分。第二、三版也没有都问清交稿期限，原记录此处概括不实 |
| S7 | 展示提案、保留每周讨论、新增周五同步、删除旧猜测且不反推相反性格 | 这些优点可由文本直接确认；未写任何存储则不能仅由某目录无匹配文件证明 |
| S8 | 完整返回新卡，边界范围更明确 | 完成后另提“测试计划”新任务，当前请求并不需要；此时尚未整卡作废，主要是多余收尾 |
| S9-b | 比基线更准确说明文本停用的范围，没有声称彻底跨会话删除 | 确认整卡作废后，又问“要不要现在就聊聊测试计划这件事本身该怎么推进？”这正是被停用卡内的事项。原记录称“未复现任何字段值”与原文不符。应补记 H4 的卡片控制失效，不能只算多余追问 |
| S9-a | 未重建整卡，说明不能控制未来上下文 | 输出记忆文件名、回收站等外部背景，且自称核查和补记规则。保留污染与操作范围问题；实际主动读写的执行链仍待证据 |

由此，技能组沟通类按现有标准至少有 **S1、S5、S6 三例 H1**，不是原报告的两例。S3 的排期让步需同一尺度复审。卡片类 S9-b 另有文本可核实的 H4。这里列出有依据的修订，不强行给 20 条再造一套看似精确的总分。

基线原文同样存在大量实质性补写，但复核时不能因基线没装 Skill 就用 Skill 专属格式处罚。比如 b-S7 少字段应区分通用的信息丢失与产品格式不一致；自查建议本身也不等于替用户承诺已完成自查。

## 4. 对反馈建议的取舍

| 建议 | 本项目判断 |
| --- | --- |
| 把承诺检查写得更具体 | 采纳。分开已做行动、可用性、交付、让步；必须同时加入正向组织话术的方法，避免文件只剩禁令 |
| 不再输出笼统自我合规认证 | 采纳。优先直接提供校验过的回复；必要时指出具体缺口或取舍。“一定让人跳过检查”只是尚待观察的影响假设 |
| “不能完成今晚整份报告”排除任何今晚沟通 | 调整。不能替用户加短聊；也不能把不能完成整份工作扩写为绝不能沟通。用户另行确认愿意手机沟通后可以采用 |
| 只能用陈述句收尾、禁止完成后的追问 | 不采纳一刀切禁令。推进当前任务的关键追问应保留；无关任务邀约和重复推销应删。S3 问真实卡点可能帮助当前申请，不应仅凭“我可以帮你”统一扣分 |
| D5 全满分，语气与表达无需再动 | 不采纳。约 900 字的 S6、S2 的长分类、S4 的责任交回都值得验证；朋友尚未评价口吻和愿意发送程度 |
| 删卡就必须主动检查全部存储 | 不采纳。普通文本作废不触发全盘核查。另有明确存储请求时，使用宿主流程并限定范围 |
| 动作声明须独立核查 | 采纳但限范围。优先保留当轮可见工具、目标与返回结果；只能获得摘要时标明转述，无法核实就 U1。评分不能为了求真擅自搜索个人数据 |
| 互不共享记忆，或随机化顺序 | 前者必要；后者只能补充。交换顺序不能清除跨条件写入的持久状态 |
| 增加版本和逐例凭证 | 采纳。开关状态、初始加载和同会话沿用分开；未知写明未知，不要求用户补造历史截图 |
| 如果用户愿意发送，应降低虚构事实修复优先级 | 不采纳。主观接受度与事实正确性分别记录。测试输入未给出的事实不能由对虚构场景的“愿意”补齐；用户提供新事实后可以生成另一个合适版本 |

## 5. 工具与记忆证据还差什么

原稿以“文件名和内容吻合”证明 s-S9a 主动检索真实发生，证据强度过高。已有信息可能由宿主自动注入，也可能来自历史检索。文本能确认接触了额外背景和作出了核查声明，不能单凭它还原本轮调用了哪些工具。

核查摘要还存在时间解释不一致：一处把规则文件归于早先 baseline 写入；末尾表格又记它创建和修改均为 19:11:25。没有当时快照，就不能据现态重建先前完整内容，更不能断言所有声明均属实。摘要本身也称“不含字段值”，同时记载了对象代称；所用“字段值”的范围不统一。

b-S9b 的“后续会话不会再读到它”超出可保证范围，后续输出也确有相关背景。但“读到停用规则及对象代称”和“重新读到完整旧卡”是两件事。前者不能直接证明后者。应按具体原句范围、可见状态与缺失证据分别记录，不替换成另一项更强结论。

下一轮将同一案例拆为两种独立条件：干净初始状态；含预置虚构旧卡/停用规则的宿主状态。记录主动读写与自动注入的区别；保留原本输出，诊断重跑另存，不用成功重跑覆盖失败。

## 6. 下一轮评测的用途

保留 S1 至 S9 作回归，补充未参与写法设计的情境，以及“少量输入 → 关键追问 → 用户补充 → 收敛话术”的完整任务。下一轮主要比较 **0.2.0 与候选新版**；Baseline 只在需要重新校准通用模型时使用，不再每次重跑完整三组。

评价先问：能否帮助用户完成本次沟通，是否保留其立场和行动自主权，是否容易找到并选用一句话。事实、承诺、卡片控制和真实动作仍逐条核对。质量高分不能抵消已确认的严重错误；只有不出错，也不足以通过有用性验收。

具体样本量、对话脚本、停止条件与人工体验门槛写入[近期设计](../../docs/superpowers/specs/2026-10-21-upward-quality-design.md)。本报告没有运行新版，也没有把方案中的示例当作实测成绩。
