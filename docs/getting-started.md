# 开始使用 Mark Talk

中文 · [English](getting-started.en.md) · [项目首页](../README.md)

先安装，再用一个真实而简单的沟通问题试一下。你不需要先整理全部聊天历史，也不需要给每个人建卡。下面的对话都是手写演示，展示输入方式和可接受的回复形态，不是效果承诺或测试实录。

## 安装和确认

### 千问桌面版工作模式

当前目录是0.3.0候选的2026-10-30修订。10月26日已在千问5.0.7.276核对恢复冻结候选d4b5032的三个文件；本次源码修订没有自动更新那份安装，也尚未在千问重新验证。版本号相同仍须核对修订日期、提交与散列，见[最新报告](../tests/reports/2026-10-29-0.3.0-human-feedback-and-refinement.md)。

试用候选时从实际源码/本地候选ZIP解压，取完整 `mark-talk/`。在支持本地导入的客户端可以发送：

```text
请从我提供的本地 mark-talk/ 目录安装技能，保留 references/upward-methods.md 和 references/relationship-card.md。
请核对 SKILL.md 版本为0.3.0、修订日期为2026-10-30，报告实际安装位置与三个文件SHA-256。没有观察到的就说明未知。
```

候选未同步远端时不要用 main 安装。需要公开0.2.0时采用[固定提交目录](https://github.com/Theo-bang2025/mark-talk-skill/tree/82dd114484f0a92068c6096c4843a68202083807/mark-talk)；旧版没有方法库，不能要求它呈现候选功能。

1. 按客户端实际本地技能入口导入；只开启这一份Mark Talk，别同时留两版。
2. 核对目录层级与三个文件，根目录README/tests不用导入。版本字符串还需配合文件散列，不能区分每次候选修订。
3. 刷新/重开后查看技能列表，再另开工作模式对话。
4. 发送例子，看核心和所需参考的可见调用证据；只有两条回复不能证明加载。日常可点名Mark Talk，自动触发测试另按固定输入。

[QwenWork官方说明](https://help.aliyun.com/zh/qwenwork/skills)给出GitHub、本地导入与 `~/.qwenworkcn/skills/`，2026-10-21已复核。其界面不能当所有千问产品的固定步骤。若实际客户端不能导入，记录入口限制，不声称安装成功。

### Codex

按[当前官方说明](https://learn.chatgpt.com/docs/build-skills)，把完整 `mark-talk/` 放进用户目录 `~/.agents/skills/`，或项目内的 `.agents/skills/`。例如：

```text
~/.agents/skills/mark-talk/SKILL.md
~/.agents/skills/mark-talk/references/relationship-card.md
~/.agents/skills/mark-talk/references/upward-methods.md
```

重新打开会话后，可以明确说“使用 `$mark-talk` 帮我回复导师”。本项目首轮曾在 `.codex/skills` 项目目录试运行，那是历史环境记录，不代表所有新版本都应沿用旧路径。

## 从一句话到可用回复

### 例一：还不知道怎样开口

你可以只说：

> 我想跟导师说进度来不及了，怎么开口？

这时缺的信息会影响承诺。AI 可以先问：

> 导师原本要你什么时候交？你现在具体卡在哪里？这两点会决定是先说明进度，还是提出调整安排。

你补充：

> 明天要初稿，实验数据还没齐。我还不知道什么时候能补齐。

一种成句回复：

> 老师，初稿还缺一部分实验数据，明天能否形成完整稿我目前不能确认。想先跟您说明一下，也请您指点：明天您更希望先看已有进展，还是等数据补齐后再看完整稿？

这里的下一步是问清导师需要先看什么，没有替你承诺明天能交已有部分。若你已确认可以交哪部分，再把那项真实能力加进去。

### 例二：赶时间，先回一句

> 领导今晚要整份报告重做。我在外地没电脑，直接给两条现在能发的，不要先问我一堆问题。

**说明约束、问清用途：**

> 我现在在外地，电脑不在身边，今晚做不了整份重做。想跟您确认，这份报告最晚什么时候要用，最需要调整的是哪部分？

**明确边界、确认优先级：**

> 收到，这个任务我需要跟您说清楚：今晚我没有电脑，没法重做整份报告。您看当前最需要先明确的是修改方向，还是另行确认完整版本的交付安排？

第一条适合尚不清楚真实时限；第二条更明确地保留今晚做不了的边界。你什么时候能开工，只有你知道，AI 应等你确认再写进消息。

### 例三：补充、选稿、改口吻

> 你：我是项目负责人，下个月上线内部工具，只有我和一位兼职同事。我想申请一位测试同事两周，怎么说有依据？
>
> 助手：你们已经做过哪些检查？两周主要需要补什么测试？这会影响怎样说明投入和缺口。
>
> 你：核心流程自测过了，跨部门账号权限还没测。我和兼职同事都没余力覆盖，希望这两周做权限验证和回归。
>
> 助手两种方向中的一条：想申请一位测试同事支援两周，主要做跨部门账号权限验证和回归。核心流程已经自测过，目前我和兼职同事都没有余力覆盖这部分。工具计划下个月上线，想请您确认能否协调人手。
>
> 你：就用这版。短一点，像平时微信，不用再给两套。
>
> 助手：想跟您申请一位测试同事支援两周，主要做账号权限验证和回归。核心流程已自测，但这部分我和兼职同事都没余力覆盖，想请您帮忙协调人手。

新增依据来自你补充的真实工作和缺口，没有编用例数、好评、风险概率、进场日期或提前归还条件。选中后默认只改这一条。你也可以一开始说“先给个简短申请”，不必按示例顺序回答。

### 例四：口吻变了，事实和立场不变

> 这条再坚定些，保留一人两周，别主动接受兼职支援，也别替我定开工日期。

可以改为：

> 这次需要申请一位测试同事支援两周，覆盖账号权限验证和回归。核心流程已自测，我和兼职同事都没有余力承担这部分，想请您协调人手。

“更坚定”不是自动升级为已决定停工或拒绝任务；“更委婉”也不是加让步。方法在内部帮助理顺内容，不要求每条固定四段、同样开头。正式邮件、熟悉的微信和你自己的常用表达可以有不同组织，不能靠随机换同义词假装自然。明确提供自己的原话通常更有帮助。

## 关系卡完整走一遍

### 创建

> 为周导师建一张卡。我是研究生，目标是顺利推进论文。我喜欢简洁表达，我们每周讨论论文，目前要改初稿。其他不知道的先留空。

卡片可以是：

```text
对象代称与角色：周导师，指导老师
我的角色：研究生
长期目标：顺利推进论文
表达偏好：简洁
已确认的互动事实：每周讨论论文
待验证判断（附依据）：无
当前未解决事项：初稿修改
最近更新时间：未记录
```

演示中未给出日期，所以写未记录；实际宿主提供了当前日期时可填当天。“表达偏好”是你希望采用的风格，不等于已经证明导师喜欢这种风格。

### 保存和下次使用

把卡片复制到你自己的笔记。下次新会话先粘贴或上传卡片，再说：

> 这是我保存的关系卡。今天导师说“先把研究问题讲清楚”，按卡片背景帮我问清下一步。

只把笔记保存到电脑，并不会让所有 AI 自动读到它。

### 纠正和预览

> 导师今天明确说每周五同步进展即可。请更新这个事实，先给我看提案。

AI 应列出建议变更和依据、给出完整提案。你核对后再替换自己的笔记。每周讨论和周五同步未必是同一件事，不应在没有确认时删掉前者。

### 删除一条，或者整卡不用

如果你带入的另一张完整旧卡中含有“导师可能喜欢每天晚上看进展”这条判断，可以单独要求：

> 删掉“导师可能喜欢每天晚上看进展”这条猜测，其他内容保留，给我完整新卡。

新的卡片应保留其他字段，待验证判断为空时写“无”。删除这里的文本不影响宿主历史或其他副本。

整张卡不再使用时，直接说：

> 这张卡整张不用了，这个对话里也别据此给建议。

AI 应停止在当前对话中采用这张卡，且不再复述字段，也不以旧事项邀请继续做任务。你之后重新提供的事实可以使用，不等于恢复旧卡。跨会话是否还会接收旧信息取决于你与宿主设置。若要管理某个具体保存文件或平台记忆，那是另外一项操作，需要明确对象，并以宿主实际执行结果为准。

## 常见卡点

| 现象 | 先检查什么 |
| --- | --- |
| 找不到技能 | 安装入口、目录层级是否多套一层、完整文件是否保留；没有入口时不要假定客户端支持 |
| 回答像普通聊天 | 看可见调用记录；日常使用可点名 Mark Talk，自动触发测试另按测试规则做 |
| 请求/汇报仍很空泛 | 检查方法库是否导入并被读取，补充真实工作或具体缺口；不需要读整本书 |
| 卡片修改不完整 | 检查 `references/relationship-card.md` 是否随目录导入，并把当前完整卡片提供给 AI |
| 新会话不知道以前的事 | 重新提供你保存的卡片；当前版本不自带跨会话数据库 |
| 回答给了未知时间或虚构进展 | 先别发送，指出具体一句并要求按已知事实重写；欢迎把匿名问题交回项目 |
| 复制粘贴后出现乱码 | 检查文件读取编码；技能指令为 ASCII 英文，用户文档为 UTF-8。不要因一条财务错误直接断言是编码导致 |

想检验是否有帮助，请用[内测指南](../tests/README.md)单独测试。日常使用的对话可以继续补背景、选方案和改口吻，正式对照则要固定输入。
