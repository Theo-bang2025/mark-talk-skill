# Mark Talk

中文 · [English](README.en.md)

给上司、导师或带教回消息时，有时难的不是礼貌，而是把自己的处境和诉求说清楚。Mark Talk 帮你从当前对话里理出重点，必要时问一两个问题，再拟出少量有不同取舍的回复，由你核对和选择。

目前聚焦职场与学业中的向上沟通：说明进度、申请资源、问清要求、表达边界。你可以只给一句背景，不必先建人物画像或上传整段聊天。

## 先看一个例子

你说：

> 主管说今天五点前要复盘定稿，但我还有一组财务数据没拿到。怎么回？

一种可以讨论的回复是：

> 复盘还缺一组财务数据，我目前没法确认五点前能齐。想跟您确认，您更需要五点前先看进展，还是等数据齐后再审定稿？

另一种侧重请对方协调：

> 复盘定稿需要的那组财务数据还没拿到，五点这个时点可能受影响。这组数据您看是否方便帮忙协调一下？也想确认，数据未齐时您希望先看哪些内容。

第一种先问清优先级；第二种提出协调请求。两种都保留了“尚不确定能否按时齐备”这个事实。以上为手写示例，用来展示使用方式，实际回答会随模型与上下文变化。

## 安装后，说你眼前的事

在千问工作模式中，可以先发送：

```text
请从 https://github.com/Theo-bang2025/mark-talk-skill 安装 mark-talk/ 这个技能文件夹，完整保留其中的 references/。安装完成后，告诉我实际安装的位置和技能版本。
```

一位参与者已在千问桌面版 `5.0.0.268` 的工作模式中，用“粘贴 GitHub 链接，由千问下载”的方式完成安装，并对旧版做了首轮试用。这是具体环境的使用记录；本次 `0.2.0` 修订仍需在该客户端复测。

安装后开启技能，另开对话就可以说：

```text
导师只说我的初稿“论证还不够扎实”。我想问清楚先改哪里，帮我拟两条微信回复。
```

如果没有自动调用，在日常使用中可明确说“使用 Mark Talk”。正式测自动触发时则保留原输入。完整步骤、手动安装和排错见[上手指南](docs/getting-started.md)。[千问办公官方文档](https://help.aliyun.com/zh/qwenwork/skills)也说明了 GitHub 链接和本地技能的安装方式；不同客户端的入口可能不同。

## 怎么把它用得更贴近自己

先给“对方说了什么、我想达到什么、我实际能做什么”。缺一项也能开始，AI 只应追问影响回复的关键内容。

| 你现在需要什么 | 可以这样说 |
| --- | --- |
| 快速回复 | “我赶时间，直接给两条现在能发的，不替我定交付时间。” |
| 争取支持 | “我想申请一名测试同事支援两周，帮我把请求讲具体。” |
| 更像自己的语气 | “第二条太正式，缩短一点。保留不接受今晚交付的意思。” |
| 先分析再写 | “先帮我看清我在这次沟通里的目标和可选做法。” |
| 复用某段关系的背景 | “按我下面这张关系卡来帮我回复；有不确定的先指出。” |

[完整示例](docs/getting-started.md#从一句话到可用回复)展示了追问、赶时间、改语气，以及关系卡从创建到作废的过程。

## 关系卡由你保管

关系卡把角色、目标、已知事实和待验证判断放在一张可读的文本里。你可以让 Mark Talk 建卡、预览修改、删掉一条猜测，或者停止使用整卡。

当前版本生成和修订卡片文本。跨会话使用时，你需要自行保存，并在下次粘贴或上传。改了新卡不等于清除了平台旧对话、平台记忆或其他副本；Skill 也不能控制平台是否自动保留历史。见[卡片示例](docs/getting-started.md#关系卡完整走一遍)与[具体规则](mark-talk/references/relationship-card.md)。

| 环境 | 已有证据与剩余限制 |

| 千问桌面版工作模式 | 参与者报告 5.0.0.268 上 GitHub 安装和旧版自动触发成功；首轮原文已复核。不是 0.2.0 的客户端复测结果。 |

| 豆包、元宝及手机端 | 本项目尚未完成直接导入和使用验证，暂不作为已支持入口。 |

技能是给宿主 AI 的工作指引，效果依赖模型与宿主。它帮助拟稿，由你选择并发送；遇到未知期限、未完成工作或未确定的让步，应先澄清，而不是补成好听的承诺。提供材料时选相关片段，并去掉无关的个人和工作敏感信息。

## 想帮忙测试

从[内测指南](tests/README.md)开始。可以把其中的提示词交给你的 AI，让它一步一步带你做。基线和技能组使用相同输入，每例独立会话；指导和评分材料不放进被测上下文。

我们保留了[历史试运行](tests/evaluation.md)和[首轮千问复核](tests/reports/2026-10-19-qwen-review.md)。复核发现旧高分漏计了未经确认的承诺，因此不把它作为普遍有效性证明。欢迎报告具体失败，也欢迎说明 Skill 没有帮助的情况。真实私聊只需给匿名摘要；标准虚构案例可以自愿提供完整回答。
