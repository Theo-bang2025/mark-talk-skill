# Mark Talk：首轮用户测评后的修订

日期：2026-10-19

本轮沿用已通过的“标准 Skill 核心 → 可控关系档案 → 平台适配与长期记忆”路线。用户授权我们复核千问内测并直接改进仓库。本次范围是首版质量与使用门槛，关系档案仍由用户保存和提供。

## 修订依据

用户提供了基线九份输出、技能九份输出文件和流程分析。技能 S9 文件含两个响应，所以实际是十八个新会话、十九次响应。S9-b 接在技能 S8 后；基线没有同样的第二轮，不能将它混入两组配对总分。

原文支持关系卡呈现与记忆边界有所改善，也暴露了技能组仍会在正文中补写交付承诺、成果判断和用户尚未接受的让步。原报告的高分漏计了这些问题；按条件分组打分也不是真正盲评。一次运行不足以估计随机波动，不能从分差推出统计稳健性。

## 三种可行改法

只润色介绍和补教程，投入少，但会保留已知的事实问题。重写整个技能和引入自动记忆，范围大，现有证据无法支持。本轮采用中间方案：保留核心交互与八字段卡，针对可复现失误修订规则，同时重建上手文档和中立评测流程。

## Skill 的行为

- 默认给两条不同策略的成句回复；第三条只有在增加不同选择时提供。事实不足但可写稳妥回复时先写；需要用户决定承诺时才追问，最多两问。
- 每条默认回复都应在已有事实下独立成立。未知姓名省略，未知期限用澄清问题表达；用户未确认的资源让步、可用时间、任务状态和阻塞原因都不写成事实。
- 模板是用户主动要求时的另一种输出，必须标明需要填写。正文外的条件说明不能让一条未知承诺变成可直接发送的回复。
- 保留具体、适量的沟通判断；需要时加一句准备建议，避免用“回复率最高”“领导一定…”等断言代替依据。
- 普通聊天和文本关系卡操作只使用本轮用户提供的材料及技能参考文件。只有用户明确请求某个文件或宿主记忆操作时，才转入该宿主的实际操作流程。动作声明要有相应证据，不把“这次未写入”推成“所有存储里都没有”。
- 关系卡输出说明保存后还需在下次主动提供；不在普通回复结尾推销建卡，也不以技能自身限制否认宿主可能具备的工具能力。

## 文档结构

中文 README 与英文 README 提供相同的定位、短示例、安装入口和能力边界。双语入门指南展示从一句背景、紧急回复、改语气到关系卡复用的完整例子。示例明确是说明用途的手写示例，不冒充测试输出。

`tests/README.md` 是内测唯一入口，`tests/ai-guide.md` 约定指导 AI 的角色；`tests/inputs.md` 只保留被测输入，`tests/scenarios.md` 留给评分者。评分表区分沟通与关系卡任务，把选项数等产品约定单独记录，避免将格式一致误当普遍质量优势。

正式对照两组各九个新会话；各组 S8 后追加 S9-b，共十八个新会话、二十次响应。两组条件、输入、工具和追问处理一致。指导/评分 AI 与被测会话分开，材料不放在被测工作区；若记忆、检索或模型版本不能隔离，按生态试用报告，仍保留具体失误。

## 证据与验收

原始“测评”目录保留在本地并排除提交。公开复核仅摘录虚构场景必要片段，区分原文观察、用户转述和未核实的宿主动作。千问兼容性更新为用户报告的成功安装及触发，不把新修订版本写成已经在千问复测通过。

改动前保留失败证据；改动后用独立会话回放关键案例和未参与修订的新情境。回归只说明被测宿主当轮表现。结构、相对链接、双语入口和两组运行计数需通过检查；无法完成的宿主验证如实保留。
