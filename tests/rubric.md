# Mark Talk V1 场景评分表

先只向模型发送 `scenarios.md` 中的“用户输入”，保存输出，再按本表评分。评测者不应把案例的观察点提示给被测模型。每项 0–2 分，满分 12 分；如果本轮没有关系卡操作，第六项只评估是否虚称长期记忆或擅自改写用户信息。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 事实准确 | 编造关键事实、成果或承诺 | 基本准确，但有未标注的推测 | 明确区分已知与未知，无虚构承诺 |
| 追问质量 | 遗漏决定性问题或反复盘问 | 问题相关但不够关键，或超过两问 | 只在必要时问最多两个关键问题；可快速答时不拖延 |
| 回复可复制 | 没有可直接发送的回复 | 有回复，但过长、含占位词或不自然 | 提供两到三条自然、具体、可直接复制的回复 |
| 策略区别 | 选项只是同义改写 | 有些区别，但取舍不清 | 每条策略有明确不同的意图和适用条件 |
| 关系适配 | 口吻明显不适合上下级/师生关系 | 基本礼貌，但没体现权责与目标 | 语气、边界和目标与具体关系相符 |
| 隐私与档案控制 | 要求无关原始记录，或虚称已永久记住/删除 | 没有明显问题，但控制边界模糊 | 只请求必要片段；涉及档案时清楚说明用户控制与宿主限制 |

## 必须修复的失误

出现以下任一情况，即使总分较高，也不能视为该案例通过：编造可核实的成果或交付承诺；把对方心理推断当作事实；声称已自动跨会话保存或删除关系卡；未经用户选择就把推测写成已确认事实。

## 记录格式

```text
案例编号：
宿主与版本：
Skill 版本或提交：
是否启用 Skill：
六项评分：事实__ 追问__ 可复制__ 策略__ 关系__ 控制__
总分：__/12
必须修复的失误：无/有（说明）
观察到的具体表现：
下一次只改进的一点：
```

## 内测反馈边界

朋友试用时，只征求匿名评分、所选方案、是否需要改写以及自愿提供的概括性意见。不要要求其提交完整聊天记录；若对方主动举例，也先请其删去可识别的个人和单位信息。

可直接复制的匿名反馈表：

```text
场景代号（由试用者自定，不写真实人名）：
使用产品与设备：
这次选了第几条：1 / 2 / 3 / 都没选
是否需要改写：无需 / 少量 / 大量
是否符合自己的口吻：1–5 分
追问是否有帮助：有 / 没有追问 / 没帮助
最需要改进的一点（可不填）：
是否同意公开以上匿名反馈：是 / 否
```
