本页记录 2026-10-05 的开发期试运行，不是 0.2.0 或 0.3.0 候选的通过报告。原六维分数按当时的旧评分口径保留；旧表将选项数量与质量混在一起，也未统一沟通和关系卡任务的判法。这些数值不与[评分表 v2](rubric.md)合并，不据此计算产品效果。新的材料见[千问内测复核](reports/2026-10-19-qwen-review.md)与[本轮回归记录](reports/2026-10-19-regression.md)。

日期：2026-10-05。宿主：Codex CLI 0.160.0，模型：gpt-6-sol。六个输入均来自 `tests/scenarios.md`，由独立的只读会话运行。启用 Skill 时，测试提示明确要求读取本项目 `mark-talk/SKILL.md`；因此下表验证的是**读取后执行的行为**。安装后的自动触发另见下文。

## 未启用 Skill 的基线

以下仅有 S1、S4 两例：实现当时尚未创建本项目的 Mark Talk Skill，用独立只读 Codex CLI 会话处理虚构请求，未通过“忽略技能”指令抑制它。完整命令、环境快照和逐次原始输出没有保存在公开记录中，因此这属于开发观察，不构成可完全复现的冻结基线。

| 案例 | 观察 |
| --- | --- |
| S1 | 只给一条回复，并替用户承诺“16:00 前同步”和“17:00 前发已完成版本”；用户并未确认这些时间和可交付内容。 |
| S4 | 只给一条回复，加入“根据试讲过程检查内容和讲法”等用户未明确提供的行动，虽在说明中提醒用户确认，回复正文仍先写成事实。 |

## 本次限制与后续验证

- `quick_validate.py` 未能运行：本机 Python 缺少 PyYAML，受限网络无法安装。已用 Python 标准库检查 frontmatter 分隔符、必填字段、目录名一致、名称格式和描述长度；这不是完整 YAML 解析校验。
- 在 Windows 的一轮自动安装试运行中，PowerShell 读取指令出现乱码，同次回复也虚构了财务指标；没有单变量实验，不能确认二者的因果关系。改成 ASCII 英文后，后续当轮没有再观察到这两项问题。此措施针对该读取路径，不保证各宿主表现相同。
- 本轮只有虚构案例，没有朋友内测，也没有千问办公、豆包或元宝的实际安装结果。

## 关系卡专项试运行

同一 Codex CLI 与模型环境下，先用仅有核心 Skill 的版本试 S7、S8，再加入关系卡规则后复测；S9 在整卡删除规则前后分别测试。这是开发期规则前后对照，**不是未启用 Skill 的裸模型基线**，也没有固定版本、只移除一个组件的完整消融实验。不能与上面的 S1/S4 基线合算。

| 案例 | 关系卡规则加入前的核心版本 | 关系卡规则加入后的版本 |
| --- | --- | --- |
| S7 纠正 | 只返回卡片的部分字段，并用“之后会按周五同步来考虑”暗示可能的长期记忆。 | 列出旧推测的删除与新事实的加入、引用用户提供的依据，输出完整建议版卡片，并说明需用户自行替换旧副本。 |
| S8 删除一条推测 | 移除了该条，但没有显式保留空的“待验证判断”字段，也未说明旧对话仍在。 | 保留全部字段，把待验证判断写为“无”，说明本次输出的删除不影响旧对话或旧副本。 |
| S9 删除整卡 | 表示本次对话不再使用卡片，也提到旧副本；对未来新会话的可控范围不够明确。 | 停止在当前回复中使用卡片，不重现卡片内容，明确新会话是否带入旧信息取决于用户和宿主平台。 |

这三条只证明文本规则在当前宿主的这些虚构案例中可执行；它们不证明平台真正提供持久化或底层数据删除能力。

## 项目目录安装后的自动触发

把 `mark-talk/` 完整复制到临时项目的 `.codex/skills/mark-talk/`，在该目录启动独立 Codex CLI 会话，不在用户提示中要求读取 Skill 文件。输入均为 `tests/scenarios.md` 中的虚构情境。

| 案例 | 观察 |
| --- | --- |
| S1 延期交付 | 自动识别 Skill，给出两条不同策略的中文回复；未补写具体财务指标或未经确认的交付时间。 |
| S8 删除一条画像推测 | 自动识别 Skill 与关系卡规则，输出八个字段的完整更新卡，将待验证判断改成“无”；明确新卡不抹除旧对话、宿主记忆、附件或另存副本。 |

临时项目位于本仓库被忽略的 `tests/_skill_smoke/`，不属于交付文件。这是 Codex CLI 项目目录的试运行；用户目录安装、Codex 图形界面、千问办公、豆包和元宝仍未实测。
